# MuseHub 第七阶段响应式适配报告

## 修改范围

- 新增 `css/responsive.css`，集中承接平板端、手机端、小手机断点的布局适配。
- 更新 `index.html`，在 `polish.css` 之后引入 `responsive.css`，并同步刷新静态资源版本号。
- 更新 `js/ui.js`，新增移动端底部 TabBar：发现、搜索、歌单、收藏、设置。
- 更新 `js/router.js`，在 hash 路由切换时回到页面顶部，避免移动端从长列表进入播放器时停留在旧滚动位置。

## 断点设计

- 桌面端：`1200px` 及以上，保持原桌面布局和横向顶部导航。
- 平板端：`768px ~ 1199px`，缩小导航间距、收窄页面边距，主内容由多列自然过渡为上下排列。
- 手机端：`max-width: 767px`，启用底部 TabBar、紧凑播放器、单列页面内容。
- 小手机：`max-width: 480px`，进一步压缩间距、卡片宽度、播放器与弹窗尺寸。

## 页面适配说明

- 首页：手机端 Hero 改为上下布局，标题缩小，搜索框全宽，来源按钮横向滑动，推荐歌单与热门词支持横向滑动，趋势歌曲变为紧凑列表。
- 搜索页：搜索框置顶，来源与分类标签横向滑动，结果列表改为紧凑歌曲卡片，右侧热搜/历史/迷你播放器移动到结果下方。
- 底部播放器：手机端改为紧凑两行布局，第一行展示封面、歌曲、播放、全屏歌词入口，第二行展示进度与时间；播放器固定在移动 TabBar 上方。
- 播放器详情页：手机端改为纵向布局，封面置顶，歌曲信息和控制按钮居中，歌词卡片和播放列表在下方自然流动。
- 歌词页：歌词内容居中，底部控制条变为移动端紧凑版，并与 TabBar 分层显示；歌词设置按钮和退出按钮保持可点。
- 收藏页：左侧菜单改为顶部横向胶囊 Tab，统计卡片在手机端保留 2 列，收藏歌曲表格转为卡片式布局。
- 歌单页与歌单详情页：手机端歌单卡片单列/双列自适应，详情页改为纵向信息区和歌曲卡片列表。
- 设置页：左侧菜单改为顶部横向 Tab，设置卡片单列，主题卡片、颜色按钮、导入导出与缓存管理均适配触摸。

## 移动端导航与播放器

- 桌面端继续使用顶部横向导航。
- 手机端顶部只保留 Logo 和小电视头像，底部显示固定 TabBar。
- 全站播放器在手机端固定于 TabBar 上方，并通过 `body.has-player-dock` 预留底部空间。
- 歌词专注页使用独立的紧凑底部播放器，同样避开 TabBar。

## 测试尺寸

已使用浏览器检查以下尺寸：首页、搜索页、播放器页、歌词页、收藏页、歌单页、设置页均无页面级横向溢出，底部播放器与 TabBar 未重叠。

- `1440 x 900`
- `1280 x 720`
- `1024 x 768`
- `768 x 1024`
- `430 x 932`
- `390 x 844`
- `375 x 667`

同时检查了控制台：无 `error`。

## 仍然存在的限制

- 手机端部分横向滚动区域中，子项会超出自身滚动容器视口，这是预期的横向滑动行为，不会造成页面级横向滚动。
- 播放器详情页在小手机上封面和控制区无法全部同时落在首屏内，需要轻微滚动查看完整控制区。
- 本阶段只做响应式适配，没有重做信息架构或移动端专属交互流程。
