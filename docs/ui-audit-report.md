# MuseHub UI 巡检报告

## 巡检页面

- `#/home` 首页 / 发现音乐
- `#/search` 搜索结果页
- `#/player` 播放器详情页
- `#/lyrics` 歌词专注页
- `#/favorites` 本地收藏页
- `#/settings` 设置页

## 发现并修复的问题

- 首页 Hero 右侧原本是 CSS 简易房间和人物占位，已替换为原创乐队房间插画，并补充小贴纸。
- 搜索页右上角原本是简化 CSS 方块人物，已替换为原创听歌搜索房间插画。
- 播放器页和歌词页背景原本主要依赖渐变和 CSS 块，已接入暖色房间背景和夜晚房间背景。
- 顶部右侧小电视头像原本是 CSS 简笔实现，已替换为透明 png 品牌头像。
- 收藏页、设置页侧栏下方原本是 CSS 简笔唱片机/摆件，已替换为生成插画。
- 首页存在轻微横向滚动溢出，已通过页面容器裁切修复。
- 空搜索结果、空收藏状态补充了透明 mascot 装饰图。
- `cover()` 组件新增 `coverUrl` / `imageUrl` 支持，保留 mock 渐变作为 fallback。
- 通过浏览器巡检确认 6 个核心路由均可访问，图片加载无失败，页面无横向溢出。

## 交互抽检结果

- 首页搜索可跳转到搜索页，并刷新结果标题。
- 搜索页收藏按钮可切换，并写入 `localStorage`。
- 设置页主题切换可保存到 `localStorage`，并立即更新页面主题类名。
- 歌曲播放按钮可更新当前歌曲，并显示底部播放器。
- 控制台巡检未发现新的 JavaScript 错误。

## 暂时保留的问题

- 歌曲、歌单、播放器封面仍是 mock 阶段的渐变占位，这是为了避免把生成图误用为音乐内容图。
- 播放器和歌词页没有真实音频播放能力，仍是第一阶段的模拟进度逻辑。
- 搜索结果数量和分类数量仍是模拟文案，后续应由真实搜索接口返回。

## 后续接入 API 注意事项

- 真实 API 返回的歌曲/专辑/MV/歌手图片应写入 `coverUrl` 或 `imageUrl`，不要替换静态装饰资源目录。
- 接口图片加载失败时继续使用 `tone-*` fallback，避免页面空白。
- 需要区分平台内容图和 UI 装饰图，避免把 `assets/bg`、`assets/images` 中的插画当成真实音乐内容。
- 接入真实音频后，播放器状态、进度、歌词时间轴需要从模拟状态迁移到音频事件驱动。
