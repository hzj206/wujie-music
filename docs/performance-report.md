# MuseHub 性能优化报告

## 图片优化

- 非首屏装饰图继续使用 `loading="lazy"`。
- 歌曲封面从纯 CSS 背景增强为真实 `img`，增加：
  - `loading="lazy"`
  - `decoding="async"`
  - 加载失败自动回退渐变封面
- 封面容器保留固定尺寸、`aspect-ratio` 与 `object-fit: cover`，减少布局跳动。
- 静态插画继续优先使用现有 `webp` 资源。

## 接口优化

- API 层统一支持：
  - 请求超时
  - 外部 AbortSignal
  - HTTP 错误处理
  - 第三方接口 `code !== 200` 的错误文案透传
- 搜索服务增加内存缓存：
  - key：`keyword + source + page + num`
  - TTL：4 分钟
  - 最大缓存项：30 条
- 搜索页增加 debounce：
  - 普通 URL 初始化搜索延迟约 180ms
  - 点击搜索按钮或 Enter 搜索立即执行
- 快速连续搜索会取消旧请求，并通过 `requestId` 与当前 URL 参数双重校验，避免旧结果覆盖新结果。
- 播放 URL 不长期缓存，避免使用过期音源地址。

## DOM 更新优化

- 播放进度更新继续走轻量 DOM 同步，不触发整页重渲染。
- 歌词高亮只切换当前行和相邻行 class。
- 歌词自动滚动只在当前歌词索引变化时触发，减少 `scrollIntoView` 频率。
- 播放器全局只创建一个 `HTMLAudioElement`，页面切换不会重复创建。
- 全局事件监听只在 `UI.init()` 绑定一次，通过事件委托处理按钮、表单、设置项和弹窗。

## 缓存策略

- `musehub:search-history`：最多 8 条，去重，最新优先。
- `musehub:recent-played`：最多 50 条，去重，最新优先。
- `musehub:song-cache`：保存搜索和播放过程中标准化后的 Song 对象，便于收藏、最近播放、歌单复用。
- `musehub:settings`：统一结构保存，读取失败时恢复默认值。
- 普通清理缓存会清除搜索历史、最近播放、播放状态和歌曲缓存，不删除收藏、歌单、稍后听和设置。

## 已知性能限制

- 当前项目仍为无构建的多 JS 文件静态页面，不能做模块级 tree-shaking 或代码分包。
- 搜索、播放、歌词依赖第三方 API，网络波动会直接影响响应时间。
- 部分列表仍采用一次性渲染，当前数据量较小可接受；如果后续支持大量本地歌曲，应考虑虚拟列表。
- 歌词和播放器状态已做轻量更新，但播放器页或歌词页在某些状态变化时仍会按现有 SPA 逻辑重渲染局部页面。
