## 本阶段修复

- 为 API 请求增加外部 `AbortSignal` 透传和超时错误文案。
- 搜索服务增加 4 分钟内存缓存，减少相同关键词、来源、页码的重复请求。
- 搜索页请求增加 debounce，并使用 AbortController 取消旧请求，防止旧结果覆盖新结果。
- 封面渲染改为真实 `img` 元素，支持 `loading="lazy"`、`decoding="async"` 和加载失败自动回退到渐变封面。
- 歌词高亮更新避免每次 `timeupdate` 都滚动，只在当前歌词变化时滚动。
- 自动换源增加最大尝试深度限制，避免失败时无限递归。
- localStorage JSON 损坏恢复改为静默兜底，避免预期恢复场景污染控制台。
- 清理缓存时同步清理搜索内存缓存。

- 真实播放测试：`晴天 - 周杰伦` 可播放，歌词同步成功。

## 仍然存在的限制

- 第三方 API 偶发超时或返回无音源时，项目只能提示或尝试换源，不能保证每首歌都可播放。
- 播放 URL 不做长期缓存，因为音源地址可能过期。
- 未知路由目前回落渲染首页，没有单独设计 404 页面。
- 手机端播放器详情页首屏不能同时容纳全部封面、信息和控制区，需要自然滚动查看。

## 下一阶段部署建议

- 增加静态资源缓存策略，给图片、CSS、JS 配置合理 `Cache-Control`。
- 使用 Nginx 或静态托管服务开启 gzip / brotli。
- 如需正式发布，可增加简单部署文档、健康检查和第三方 API 不可用时的降级说明。
- 后续若引入构建工具，可再做资源 hash、图片压缩、按需拆分和更严格的 lint。
